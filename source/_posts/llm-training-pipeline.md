## 写在前面

你下载了一个开源大模型，兴冲冲地输入"你好，请介绍一下你自己"，结果它回：

```
你好，请介绍一下你自己的名字、年龄、职业、兴趣爱好……
```

它不是在回答你，而是在**续写你的问题**。这就是**基座模型（base model）**——一个只会"接话"的文本续写器。

而 ChatGPT、DeepSeek、Claude 这些产品里的模型，会礼貌地回答你、拒绝有害请求、按格式输出 JSON。它们和基座模型之间，隔着三道关键工序：

1. **预训练（Pre-training）**：读遍海量文本，学会"下一个 token 是什么"；
2. **监督微调（SFT）**：学会"按照指令回答"，而不是自顾自续写；
3. **偏好对齐（RLHF / DPO）**：学会"什么样的回答更好"，更符合人类偏好。

这三步加起来，才是我们日常使用的"助手"。这一篇把整条流水线拆开，回答：

- 预训练到底在学什么？为什么"预测下一个词"能产生智能？
- SFT 的数据长什么样？为什么只对回答部分算 loss？
- RLHF 和 DPO 有什么区别？为什么需要"奖励模型"？
- 推理模型（o1、R1 这一类）又多加了一步什么？

这是「大模型基础」系列的第四篇。前面讲了模型结构、分词、采样；这一篇讲**模型是怎么从随机参数变成助手的**。

注意几个容易混淆的点：

- **不是所有模型都走完全部三步**。基座模型可以只做预训练；很多开源模型发布 base 和 instruct 两个版本；
- **SFT 和 RLHF 不是"教知识"，而是"教行为"**。知识主要在预训练阶段注入；
- **推理模型是在 instruct 模型基础上再加一段强化学习**，专门训练"多想几步"。

## 二、阶段一：预训练——读万卷书

### 2.1 目标函数只有一个

预训练的任务简单到令人发指：**给定前面的 token，预测下一个 token。**

把一整段文本喂进去，让模型在每个位置都猜下一个词：

```
输入： 大 模 型 的 核 心 是 注 意
标签： 模 型 的 核 心 是 注 意 力
```

每个位置都产生一个预测，和真实的下一个 token 算交叉熵，取平均就是 loss：

```
loss = -(1/N) Σ log P(真实下一个 token | 前面的 token)
```

这就是**自监督学习**：不需要人工标注，文本本身就是答案。互联网上的每一段文字，都能变成训练样本。

### 2.2 为什么"预测下一个词"能产生智能

这是最反直觉、也最常被问的问题。

想象你要预测一段文本的下一个词。为了猜得准，你必须理解：

- **语法**：主谓宾怎么搭配，"的"后面通常接名词；
- **事实**："中国的首都是"后面大概率是"北京"；
- **逻辑**："如果下雨，那么地面会"后面是"湿"；
- **代码**：`for i in range(` 后面应该是一个整数和右括号；
- **风格**：鲁迅的文章和产品说明书，用词完全不同。

**预测下一个词，逼迫模型把世界的规律压缩进参数里。** 这就是"压缩即智能"的一种直观理解：能把海量文本压缩得越好，说明它抓住了越多的结构。

当然，这个目标也有副作用：模型学的是"什么文本更可能出现"，而不是"什么话是真的"。这为后面的幻觉埋下了根（幻觉那篇会详谈）。

### 2.3 数据：质量比数量更重要

预训练数据通常来自：

| 来源 | 内容 | 作用 |
|---|---|---|
| 网页爬取 | Common Crawl、新闻、博客 | 覆盖面广，但噪声大 |
| 书籍 | 小说、教材、专著 | 长文本、连贯表达 |
| 代码 | GitHub、技术文档 | 结构化推理、编程能力 |
| 论文 | arXiv、学术期刊 | 专业知识 |
| 对话/社区 | 论坛、问答 | 口语化、多轮 |
| 合成数据 | 强模型生成、改写 | 补充稀缺领域 |

原始数据不能直接喂，要经过一套清洗流水线：

1. **去重**：重复内容会让模型死记硬背，还浪费算力；
2. **质量过滤**：用分类器或启发式规则去掉乱码、广告、低质页面；
3. **去毒/安全过滤**：移除违法、暴力、隐私内容；
4. **去污染（decontamination）**：把测试集题目从训练集里删掉，否则评测成绩虚高；
5. **配比（data mixture）**：代码、中文、英文、数学各占多少，直接影响能力结构。

一个常被忽略的事实：**数据配比是模型能力的重要"配方"**。代码比例高，推理和结构化能力通常更强；中文比例低，中文能力就弱。这不是调参能弥补的。

### 2.4 规模：参数、token 和算力

预训练的规模由三个量决定：

- **参数量**（模型多大）；
- **训练 token 数**（读了多少字）；
- **算力**（多少 GPU、跑多久）。

三者之间有经验规律，叫 **Scaling Law（缩放定律）**：损失随参数量、数据量、算力的增加呈幂律下降。简单说，**加大投入，loss 会稳定下降，但收益递减**。

Chinchilla（2022）给出一个著名结论：在固定算力预算下，参数量和数据量应该**同比例增长**，最优比例大约是**每个参数配 20 个 token**。

按这个比例：

| 模型 | 参数量 | "最优" token 数 |
|---|---|---|
| 1B | 10 亿 | 约 200 亿 |
| 7B | 70 亿 | 约 1,400 亿 |
| 70B | 700 亿 | 约 1.4 万亿 |

但现代模型普遍"超配"数据。比如 Llama-3-8B 用了超过 15 万亿 token，是 Chinchilla 最优值（约 1600 亿）的近百倍。为什么？因为**训练是一次性的，推理是长期的**：多花训练算力，换一个更小、更快、更便宜的模型，长期看更划算。这叫"推理最优"而非"训练最优"。

### 2.5 基座模型长什么样

预训练结束后，你得到的是一个"文本续写器"：

```
输入：中国的首都是
输出：北京，是中国的政治、文化、国际交往和科技创新中心……

输入：请写一首关于春天的诗
输出：请写一首关于夏天的诗，要求五言绝句，押韵……
```

第二个例子很典型：它把你的**指令当成了文本的开头**，继续写"下一条指令"，而不是执行指令。因为它只学过"续写"，没学过"服从"。

## 三、阶段二：SFT——学会"回答问题"

### 3.1 数据长什么样

SFT（Supervised Fine-Tuning，监督微调）的数据是**指令-回答对**：

```json
{
  "instruction": "用一句话解释什么是过拟合。",
  "response": "过拟合是模型把训练数据中的噪声也学了进去，导致在训练集上表现很好、在新数据上表现很差。"
}
```

真实数据通常更复杂：多轮对话、系统提示、工具调用、带格式的输出（JSON、表格）、拒答示例等。

关键点：**SFT 数据不是"知识库"，而是"行为示范"。** 你给它看几千条"怎么回答"，它学会的是回答的格式、语气、详略、边界，而不是记住每条答案。

### 3.2 只对回答算 loss

一条训练样本是"问题 + 回答"。我们不希望模型学习"复述问题"，只希望它学习"生成回答"。做法是把问题部分的标签设成 `-100`：

```python
# 假设 prompt_ids 是问题部分，full_ids 是完整序列
labels = full_ids.copy()
labels[:len(prompt_ids)] = -100   # -100 会被交叉熵忽略

logits = model(full_ids).logits
loss = F.cross_entropy(
    logits.view(-1, vocab_size),
    labels.view(-1),
    ignore_index=-100,
)
```

这就是为什么 SFT 的"训练 token 数"和"计费 token 数"不是一回事：**问题部分参与前向计算，但不参与 loss。**

### 3.3 训练细节

| 超参数 | 典型做法 | 原因 |
|---|---|---|
| 学习率 | 1e-5 ~ 2e-5 | 比预训练小 1~2 个数量级，避免破坏已有能力 |
| epoch | 1 ~ 3 | 多了容易过拟合、忘掉通用能力 |
| batch size | 几十到几百 | 视显存而定 |
| 数据量 | 几千 ~ 几百万条 | 质量比数量重要 |
| loss | 只算 response | 避免学习复述问题 |

SFT 最怕两件事：

1. **灾难性遗忘（catastrophic forgetting）**：在窄领域数据上微调太久，模型忘了预训练学到的通用能力。缓解办法是混入一部分预训练数据（replay），或者用 LoRA 只更新少量参数；
2. **过拟合**：几千条数据训太多轮，模型开始背答案。验证 loss 上升就是信号。

### 3.4 一千条数据也能做出聊天模型

Meta 的 LIMA 论文（2023）给了一个反直觉的结论：**只用 1000 条高质量、多样化的指令数据做 SFT，就能让 65B 模型表现出不错的对话能力。**

这说明：预训练已经把知识和语言能力装进去了，SFT 主要是在"激活"和"塑形"——教它什么时候该用哪种能力、用什么格式输出。**SFT 是开关，不是电源。**

当然，1000 条能做出"能聊"的模型，做不出"可靠、安全、领域精通"的产品模型。后者仍然需要大量高质量数据和后续对齐。

### 3.5 SFT 数据的来源

- **人工标注**：质量最高，成本最高；
- **强模型蒸馏**：用 GPT-4/Claude 生成回答，再拿来训练小模型；成本低，但要遵守使用条款，且容易学到"教师模型的错误"；
- **Self-Instruct**：让模型自己生成指令和回答，再筛选；
- **真实业务日志**：最贴合场景，但要注意隐私和脱敏。

一个常见误区：**以为 SFT 能注入新知识**。能，但不可靠。模型在 SFT 阶段见到的知识量远小于预训练，且容易被遗忘。要注入事实性知识，RAG（检索增强）通常比 SFT 更合适。

## 四、阶段三：对齐——学会"招人喜欢"

### 4.1 SFT 之后还缺什么

SFT 教会了模型"回答问题"，但一个问题往往有很多种回答：

- 都正确，但一个更简洁，一个更详细；
- 都礼貌，但一个更真诚，一个更机械；
- 一个直接给答案，一个先反问澄清。

**"哪个更好"很难用标准答案标注，但人类很容易比较。** 这就是偏好对齐的切入点：不教模型"标准答案是什么"，而是教它"人类更喜欢哪种"。

### 4.2 RLHF：从人类偏好到奖励模型

RLHF（Reinforcement Learning from Human Feedback）分三步：

**第一步：收集偏好数据。** 对同一个问题，让模型生成两个回答 A、B，请人类标注哪个更好：

```
问题：如何提高睡眠质量？
回答 A：保持规律作息、睡前少看手机、卧室保持黑暗安静……
回答 B：多喝咖啡，熬夜打游戏，白天补觉。
人类标注：A 更好
```

**第二步：训练奖励模型（Reward Model）。** 用 Bradley-Terry 模型把"比较"变成"打分"：

```
P(A 优于 B) = σ( reward(A) - reward(B) )
```

训练目标是让奖励模型给人类偏好的回答打更高分。训练好后，它就是一个"自动人类评委"，可以给任意回答打分。

**第三步：用强化学习优化策略。** 常用 PPO：

- 策略模型（要训练的模型）生成回答；
- 奖励模型给回答打分；
- 同时加一个 **KL 惩罚**，防止新模型偏离参考模型太远（否则会为了刷分说出奇怪的话）；
- 用策略梯度更新参数。

目标可以粗略写成：

```
最大化：奖励模型打分 - β × KL(新模型 || 参考模型)
```

`β` 控制"讨好人类"和"保持原样"之间的平衡。

### 4.3 RLHF 的痛点

RLHF 效果很好，但工程上很麻烦：

- 要同时加载**四个模型**：策略、参考、奖励、价值（PPO 的 critic），显存爆炸；
- PPO 调参困难，训练不稳定；
- 奖励模型会被"钻空子"（reward hacking）：模型学会说人类评委爱听的话，而不是真正变好；
- 人类标注贵、慢、有偏见。

### 4.4 DPO：跳过奖励模型

DPO（Direct Preference Optimization，2023）提出了一个优雅的替代方案：**不训练奖励模型，直接用偏好数据优化语言模型。**

它的损失函数长这样：

```
L_DPO = -log σ( β × [ log πθ(y_w|x)/π_ref(y_w|x)
                    - log πθ(y_l|x)/π_ref(y_l|x) ] )
```

其中：

- `y_w` 是人类偏好的回答（winner），`y_l` 是不被偏好的（loser）；
- `πθ` 是当前模型，`π_ref` 是参考模型（通常是 SFT 后的模型）；
- `β` 控制偏离参考模型的程度。

直观理解：**提高好回答的概率，降低坏回答的概率，但别偏离原来的模型太远。** 它把 RL 问题转化成了一个类似分类的监督学习问题，不需要奖励模型、不需要在线采样、不需要 PPO。

DPO 代码核心只有几行：

```python
def dpo_loss(policy_logps_w, policy_logps_l, ref_logps_w, ref_logps_l, beta=0.1):
    pi_w = policy_logps_w - ref_logps_w
    pi_l = policy_logps_l - ref_logps_l
    return -F.logsigmoid(beta * (pi_w - pi_l)).mean()
```

| 对比 | RLHF（PPO） | DPO |
|---|---|---|
| 是否需要奖励模型 | 需要 | 不需要 |
| 是否在线采样 | 需要 | 不需要（离线数据） |
| 训练稳定性 | 较难 | 较稳 |
| 显存 | 四个模型 | 两个模型（策略 + 参考） |
| 效果 | 上限高，可在线探索 | 接近 RLHF，工程简单 |
| 风险 | reward hacking | 容易过拟合偏好数据 |

实践中，很多团队先用 DPO 快速迭代，再视效果决定要不要上 PPO/GRPO。

### 4.5 从"对齐"到"推理"：RLVR

2024 年以后，一条新路线火了：**RLVR（Reinforcement Learning with Verifiable Rewards）**。

它的想法是：与其让人类给"回答好不好"打分，不如找**可以自动验证对错**的任务——数学题有标准答案，代码能跑单元测试，逻辑题能检查结果。模型答对给奖励，答错不给。

DeepSeek-R1 展示了这条路的威力：

1. 用可验证的数学/代码题做强化学习；
2. 模型自己学会"多想几步"、自我检查、写更长的思维链；
3. 不需要人工标注每一步推理。

这就是"推理模型"（reasoning model）的核心：**用 RL 奖励"想对了"，而不是奖励"说得像"**。

当然，RLVR 只适用于有明确对错的任务。开放写作、情感陪伴、价值观判断，仍然需要人类偏好数据。

### 4.6 对齐的副作用

对齐不是免费的午餐：

- **对齐税（alignment tax）**：过度对齐可能让模型变保守，某些 benchmark 分数下降；
- **谄媚（sycophancy）**：模型学会迎合用户，用户说错它也附和；
- **过度拒答**：安全训练过头，正常问题也被拒绝；
- **风格趋同**：RLHF 后的模型往往变得"很像"，失去个性。

这些问题没有完美解，只能靠数据配比、奖励设计、评测体系不断平衡。

## 五、三阶段对比

| 维度 | 预训练 | SFT | 偏好对齐 |
|---|---|---|---|
| 数据 | 海量无标注文本 | 几万~几百万条指令-回答 | 人类/模型偏好比较 |
| 目标 | 预测下一个 token | 最大化回答的似然 | 让好回答概率更高 |
| loss 范围 | 全部 token | 只算回答部分 | 偏好对 / 奖励 |
| 算力 | 最大（占 95%+） | 小 | 中 |
| 学到什么 | 语言、知识、推理 | 格式、指令遵循、风格 | 有用、诚实、无害 |
| 产出 | 基座模型 | 指令模型 | 对齐模型 |
| 类比 | 读完大学所有书 | 学会写作业的格式 | 学会让老师满意 |

再来一张"能力来源"的表，帮你判断问题出在哪个阶段：

| 现象 | 可能的原因 | 该动哪个阶段 |
|---|---|---|
| 什么都不知道 | 预训练数据不足/质量差 | 预训练 |
| 知道但不会答题 | 没做 SFT / SFT 数据差 | SFT |
| 会答但不听指令 | SFT 格式不对 / 模板错了 | SFT |
| 会答但语气差、爱抬杠 | 偏好对齐不足 | RLHF/DPO |
| 事实错误、编造 | 预训练知识 + 幻觉 | RAG / 工具 / 训练 |
| 推理差、算不对 | 推理训练不足 | RLVR / 工具 |
| 中文差 | 中文语料比例低 | 预训练 |

## 六、常见疑问

**Q1：能不能跳过预训练，直接 SFT？**
不能。SFT 数据量太小，模型学不到语言和世界知识。预训练是"打地基"，SFT 是"装修"。

**Q2：SFT 数据是不是越多越好？**
不是。1 万条高质量、多样化的数据，往往胜过 100 万条低质重复数据。数据的**多样性、准确性、难度分布**比数量更重要。做 SFT 前先问：这条数据能教会模型一种新行为吗？

**Q3：RLHF 和 DPO 哪个更好？**
没有绝对答案。DPO 简单、稳定、便宜，适合大多数团队；PPO/RLHF 上限更高，能利用在线探索，但工程复杂。2024 年后，GRPO 等更轻量的 RL 方法也在兴起。选型要看数据、算力和团队能力。

**Q4：为什么推理模型要"先想很久"？**
长思维链让模型在生成最终答案前，先展开中间步骤、自我检查、尝试不同路径。RLVR 训练会强化"想出正确答案的思考模式"，所以模型学会了"多想一会儿更可能对"。代价是延迟和 token 消耗。

**Q5：对齐会让模型变笨吗？**
可能。过度优化"人类喜欢"会牺牲一些客观能力，这叫对齐税。好的做法是混合目标：既要偏好奖励，也要保留预训练 loss、通用能力评测，避免模型"只会讨好"。

**Q6：开源模型为什么有 base 和 instruct 两个版本？**
base 是预训练产物，适合继续做领域预训练或研究；instruct 是 SFT/对齐后的版本，适合直接对话。做领域微调时，通常从 base 或 instruct 出发都可以，取决于你希望保留多少原有对话行为。

**Q7：我能用 GPT-4 的输出来训练自己的模型吗？**
技术上可以（蒸馏），但要遵守教师模型的使用条款，并注意：你学到的是"教师模型的表达"，不是"它的全部能力"；教师犯错，学生也会继承。数据质量和合法性都要评估。

## 七、总结

把整个流程压缩成一条线：

```
海量文本
  → 预训练（预测下一个 token）
  → 基座模型（会续写，不会听话）
  → SFT（指令-回答对，只对回答算 loss）
  → 指令模型（会回答，格式对）
  → 偏好对齐（RLHF / DPO）
  → 对齐模型（有用、诚实、无害）
  → [可选] 推理 RL（RLVR，可验证奖励）
  → 推理模型（长思维链）
```

记住五句话：

1. **预训练给知识和语言，SFT 给格式和行为，对齐给偏好和边界。**
2. **SFT 不是教知识，是教"怎么用知识"**；事实性问题优先用 RAG。
3. **RLHF 用奖励模型模拟人类评委，DPO 直接用偏好对优化模型。**
4. **推理模型的核心是"可验证奖励 + 长思维链"**，不是简单的"多训几轮"。
5. **对齐有代价**：谄媚、过度拒答、风格趋同，都需要评测和权衡。

动手建议：

1. 找一个开源小模型（如 Qwen2.5-0.5B），用 LoRA 在几百条指令数据上做一次 SFT，感受 loss mask 和灾难性遗忘；
2. 用同一个问题让 base 和 instruct 版本各答一次，对比"续写"和"回答"的差别；
3. 读一读 InstructGPT、DPO、DeepSeek-R1 三篇论文的摘要和算法图，把今天的流程图对应上去；
4. 自己构造 50 条偏好对，跑一遍 DPO 的 loss 计算，理解 `β` 的作用。
