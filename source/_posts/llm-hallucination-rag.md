## 写在前面

我见过最离谱的一次：让某模型推荐几篇"关于大模型幻觉"的论文，它一口气给了五篇，标题、作者、年份、期刊全都像模像样——**但没有一篇真实存在**。

更麻烦的是，它说得很自信。没有"可能""大概"，没有犹豫，甚至连引用格式都给你排好了。你如果不去查，根本发现不了。

这就是**幻觉（Hallucination）**：模型生成了流畅、自信、但**不符合事实**或**没有依据**的内容。

很多人把它当成"模型还不够强"的 bug，等下一代就好了。但这一篇想告诉你：

> 幻觉不是偶然的故障，而是"预测下一个 token"这个训练目标的**结构性副产品**。它不会消失，只能被管理。

我们会讲清楚：

- 幻觉分哪两种，各自怎么产生；
- 为什么模型"不知道自己不知道"；
- RAG 到底怎么接，为什么它不能包治百病；
- 用 100 行纯 Python 手撕一个迷你检索系统，跑通"检索—增强—生成"的骨架；
- 怎么评估一个 RAG 系统到底靠不靠谱。

这是「大模型基础」系列的第六篇，也是最后一篇。前面讲了模型怎么读字、怎么生成、怎么训练、记忆为什么贵；这一篇讲它最常被诟病的毛病，以及工程上的应对。

## 一、幻觉的两种类型

学术界通常把幻觉分成两类，这个分类很实用，因为**解法完全不同**。

### 1.1 事实性幻觉（Factuality Hallucination）

模型说了一个与客观事实不符的内容：

- 编造不存在的论文、法条、书籍、人物；
- 把 2023 年的事件说成 2021 年；
- 把某个 API 的参数名记错；
- 给出一个看似合理但错误的数字。

这类幻觉的根源是**知识问题**：模型没记住，或者记错了，或者训练数据本身有错。

### 1.2 忠实性幻觉（Faithfulness Hallucination）

模型说的话可能本身没错，但**和你给它的资料/上下文不一致**：

- 你给它一份文档，它总结时加入了文档里没有的内容；
- 你让它"只根据以下资料回答"，它却用了自己的先验知识；
- 多轮对话里前后矛盾；
- 引用来源标错，答案对但出处不对。

这类幻觉的根源是**遵循问题**：模型没有忠实地使用上下文，或者注意力被带偏了。

| 类型 | 表现 | 主要原因 | 优先解法 |
|---|---|---|---|
| 事实性 | 编造事实、张冠李戴 | 知识缺失/错误、知识截止 | RAG、工具、训练 |
| 忠实性 | 偏离资料、自相矛盾 | 上下文利用不足、指令遵循差 | 提示词、引用、微调 |

先分清是哪一种，再谈怎么修。很多团队一上来就微调，结果发现是检索没做好，白花算力。

## 二、为什么模型会"编"

### 2.1 训练目标里没有"真"这个字

预训练的目标是：

```
最大化 P(下一个 token | 前面的 token)
```

它奖励的是"**像人写的**"，不是"**是真的**"。一个编造得很合理的句子，在语言模型看来可能比一个诚实但生硬的句子"更可能"。

比如：

```
问：爱因斯坦 1921 年获得诺贝尔奖，是因为提出了什么理论？
```

真实答案是"光电效应"（不是相对论）。但语料里"爱因斯坦—相对论—诺贝尔奖"共现的次数极多，模型很容易顺着最"顺口"的关联说出"相对论"。**统计关联压倒了事实核查。**

### 2.2 知识是压缩的，而且有损

模型把海量文本压缩进几百亿参数，不可能逐字保存。高频知识（"北京是中国首都"）记得牢，长尾知识（某篇论文的第三作者、某个小城的邮编）就容易糊。

更麻烦的是，模型**不知道自己哪里没记住**。它没有"记忆索引"，无法区分"我很确定"和"我在猜"。于是它用同样的自信语气说出两者。

### 2.3 知识截止与"不知道"

模型训练数据有截止日期。截止之后的事，它不知道。但它往往不会说"我不知道"，而是用旧知识硬答：

```
问：2026 年世界杯冠军是谁？
（训练数据截止时还没举办）
模型：可能是巴西队，他们阵容强大……
```

这不是撒谎，是**在缺少信息时仍然要给出一个"最可能的续写"**。

### 2.4 上下文太长，注意力被稀释

即使你把资料贴进去了，模型也不一定用得上。长上下文里，关键信息可能被大量无关内容淹没；放在中间位置的信息尤其容易被忽略（*Lost in the Middle*）。

这就是"忠实性幻觉"的常见来源：**资料在，但没被"看见"。**

### 2.5 解码的随机性

采样温度高、top-p 大，模型更可能选低概率词，幻觉概率上升。但注意：**温度调到 0 也不能消除幻觉**，它只是减少随机性，不改变模型"不知道"的事实。

### 2.6 对齐的副作用：宁可编，不可拒

SFT/RLHF 的数据往往偏好"给出答案"而不是"拒绝回答"。一个总是说"我不知道"的助手，人类评委不喜欢。久而久之，模型学会了**先编一个再说**。

再加上**谄媚（sycophancy）**：用户说"我觉得是 A"，模型容易顺着说"A 有道理"，哪怕 A 是错的。

### 2.7 训练数据本身有错

网页、论坛、旧文档里充满错误和过时信息。模型不会自动辨别真伪，它只学"什么文本常见"。错误信息被重复得足够多，也会被当成"知识"。

## 三、幻觉不是纯粹的 bug

这里要泼一盆冷水：**只要模型是在"生成"而不是"检索数据库"，幻觉就不可能降为零。**

原因在于"生成"的本质是**在不确定时做最合理的补全**。人类也一样：让你凭记忆画一张没去过的城市地图，你会画出一个"看起来合理"的版本，而不是空白。

所以工程目标不是"消灭幻觉"，而是：

1. **降低发生率**：让模型在关键事实上更可靠；
2. **提高可发现性**：让错误容易被发现（引用、来源、置信度）；
3. **限制影响面**：高风险场景加人工复核、加工具验证、加兜底。

一句行业里常说的话：**没有零幻觉的模型，只有可接受的失败率。**

## 四、缓解手段：从提示词到训练

按"改动成本"从低到高排：

| 层级 | 手段 | 作用 | 局限 |
|---|---|---|---|
| 提示词 | 要求"只依据资料回答"、要求引用、允许说"不知道" | 低成本，立竿见影 | 模型可能不遵守 |
| 解码 | 降温度、约束解码、结构化输出 | 减少随机性 | 不解决知识缺失 |
| 检索 | RAG、搜索、数据库查询 | 补充实时/私有知识 | 检索错就全错 |
| 工具 | 计算器、代码执行、API 调用 | 把"算"和"查"交给确定性系统 | 需要工程接入 |
| 验证 | 自我一致性、多模型交叉、规则校验 | 发现部分错误 | 增加成本/延迟 |
| 训练 | 事实性 RLHF、拒答数据、过程监督 | 改变模型行为 | 成本高，可能遗忘 |
| 产品 | 显示来源、人工复核、风险分级 | 控制影响 | 不提升模型本身 |

### 4.1 提示词：先让模型"有据可依"

一个实用的系统提示：

```
你是一个严谨的助手。回答必须遵守：
1. 只能依据【参考资料】回答，不得使用资料之外的知识；
2. 每个关键结论后标注来源编号，如 [1]；
3. 如果资料中没有答案，直接回答"根据现有资料无法确定"，不要猜测；
4. 不要编造引用、数字、日期。
```

注意第 3 条：**显式允许"不知道"**，比反复强调"要准确"更有效。很多幻觉是因为模型觉得"必须给个答案"。

### 4.2 工具：让确定的事交给确定的系统

- 算术 → 计算器/代码解释器；
- 实时信息 → 搜索 API；
- 私有数据 → 数据库/知识库；
- 格式 → JSON Schema 约束解码。

模型负责"理解意图、组织语言"，工具负责"给出事实"。这是目前最可靠的组合。

### 4.3 自我一致性：多问几遍

对同一个问题采样多次，取多数一致的答案（Self-Consistency）。它对**推理题**有效，因为正确路径往往收敛到同一答案；对开放式事实题效果有限，而且成本翻倍。

### 4.4 训练：让"承认不知道"成为好行为

在 SFT/RLHF 数据里加入"资料不足时拒答"的样本，并用偏好数据奖励"有依据的回答"、惩罚"编造"。这能改变模型的默认行为，但需要持续维护，且可能带来过度拒答。

## 五、RAG：给模型接一个"开卷考试"

RAG（Retrieval-Augmented Generation，检索增强生成）是目前最主流的幻觉缓解方案。它的核心思想一句话：

> **不要让模型凭记忆答题，先帮它把相关资料找出来，放在卷子旁边。**

### 5.1 完整流水线

{% mermaid %}
flowchart LR
    Q["用户问题"] --> QP["查询改写/扩展"]
    QP --> RET["检索 Top-k"]
    KB["文档库"] --> PARSE["解析/清洗"] --> CHUNK["分块"] --> EMB["向量化"] --> VDB["向量库"]
    VDB --> RET
    RET --> RR["重排序 Rerank"]
    RR --> CTX["组装上下文"]
    CTX --> LLM["大模型生成"]
    LLM --> ANS["答案 + 引用"]
    ANS --> EVAL["评估/兜底"]
{% endmermaid %}

拆开看每一步：

1. **文档解析**：PDF、Word、网页、数据库，先转成纯文本；
2. **清洗**：去页眉页脚、去乱码、保留标题层级；
3. **分块（chunking）**：把长文档切成几百字的片段，块间留重叠；
4. **向量化（embedding）**：用嵌入模型把每个块变成向量；
5. **建索引**：存进向量库（FAISS、Milvus、pgvector 等）；
6. **查询改写**：把用户口语化的问题改写成适合检索的查询；
7. **检索**：找最相似的 top-k 个块；
8. **重排序（rerank）**：用交叉编码器对候选精排，取最相关的几个；
9. **组装 prompt**：把资料、问题、回答要求拼在一起；
10. **生成**：模型基于资料回答，并标注引用；
11. **评估与兜底**：检索分数低、资料冲突时，触发"不知道"或转人工。

### 5.2 为什么 RAG 能降低幻觉

- 模型不需要"记住"，只需要"读"；
- 资料是最新的、私有的、可追溯的；
- 回答可以附来源，方便核对；
- 资料里没有的，可以明确说"没有"。

但 RAG 不是银弹：**检索错了，模型会一本正经地根据错误资料回答**，而且看起来更有说服力。这叫"garbage in, garbage out"。

## 六、手撕一个迷你 RAG

下面这段代码不依赖任何第三方库，用"字符二元组 + TF-IDF + 余弦相似度"实现检索，把 RAG 的骨架跑通。

### 6.1 文档与分块

```python
import math
import re
from collections import Counter

DOCS = [
    ('员工手册-年假', '员工入职满一年可享受 5 天年假，满三年 10 天，满五年 15 天。'
                      '年假需提前 3 个工作日在 OA 系统提交申请，经直属主管批准后生效。'
                      '当年未休完的年假最多结转 5 天到次年。'),
    ('员工手册-报销', '差旅住宿标准：一线城市每晚不超过 600 元，二线城市每晚不超过 400 元，'
                      '其他城市每晚不超过 300 元。发票需在费用发生后 30 天内提交。'),
    ('员工手册-远程办公', '员工每周最多可申请 2 天远程办公，需提前一天获得直属主管批准。'
                          '远程办公期间须保持在线，参加视频会议时需开启摄像头。'),
    ('员工手册-培训', '公司为每位员工提供每年 5000 元的学习预算，可用于课程、书籍和认证考试。'
                      '使用预算需提前在 OA 提交申请，课程结束后 10 个工作日内提交学习心得。'),
    ('员工手册-设备', '入职时配发笔记本电脑和显示器。笔记本使用满 3 年可申请换新，'
                      '显示器使用满 5 年可申请换新。设备人为损坏需说明原因。'),
    ('员工手册-班车', '公司提供早晚班车，覆盖地铁 1 号线和 5 号线沿线。班车座位需提前一天预约，'
                      '未预约不能乘车。加班到 21 点后可申请打车报销。'),
]

def chunk_text(text, size=70, overlap=10):
    chunks, start = [], 0
    while start < len(text):
        end = min(start + size, len(text))
        chunks.append(text[start:end])
        if end == len(text):
            break
        start = end - overlap          # 块之间留 10 个字的重叠
    return chunks

chunks = []
for title, text in DOCS:
    for i, piece in enumerate(chunk_text(text)):
        chunks.append({'title': title, 'chunk_id': i, 'text': piece})
```

为什么要重叠？因为一句话可能正好被切断。重叠能让相邻块都保留完整的语义片段。

### 6.2 检索：TF-IDF + 余弦

中文没有空格，这里用**字符二元组**当 token：`"年假有几天"` → `["年假", "假有", "有几", "几天"]`。

```python
def tokenize(text):
    text = re.sub(r'\s+', '', text)
    return [text[i:i+2] for i in range(len(text)-1)]

# 统计每个 token 出现在多少个块里（文档频率）
df = Counter()
for c in chunks:
    for t in set(tokenize(c['text'])):
        df[t] += 1
idf = {t: math.log((len(chunks)+1)/(df[t]+1)) + 1 for t in df}

def tfidf_vec(text):
    toks = tokenize(text)
    tf = Counter(toks)
    vec = {t: (n/len(toks)) * idf.get(t, 0) for t, n in tf.items()}
    norm = math.sqrt(sum(v*v for v in vec.values())) or 1.0
    return {t: v/norm for t, v in vec.items()}

def retrieve(query, top_k=2):
    qv = tfidf_vec(query)
    scored = [(sum(v * c['vec'].get(t, 0) for t, v in qv.items()), c) for c in chunks]
    return sorted(scored, key=lambda x: x[0], reverse=True)[:top_k]

for c in chunks:                       # 建索引时提前算好每个块的向量
    c['vec'] = tfidf_vec(c['text'])
```

真实运行结果（节选，分数为余弦相似度）：

```
问题: 年假有几天？
  [0.231] 员工手册-年假#0: 员工入职满一年可享受 5 天年假，满三年 10 天，满五年 15 天。...
  [0.178] 员工手册-年假#1: 直属主管批准后生效。当年未休完的年假最多结转 5 天到次年。...

问题: 出差住宿能报多少钱？
  [0.097] 员工手册-报销#0: 差旅住宿标准：一线城市每晚不超过 600 元，二线城市每晚不超过 400 元...

问题: 笔记本用多久可以换新？
  [0.394] 员工手册-设备#0: 入职时配发笔记本电脑和显示器。笔记本使用满 3 年可申请换新...

问题: 可以带宠物上班吗？
  [0.000] 员工手册-年假#0: ...
  -> 检索分数过低，触发"不知道"兜底
```

最后一行是关键：**当所有检索分数都接近 0 时，不要硬答**。生产系统里这个阈值要基于验证集调，而不是拍脑袋。

### 6.3 组装 prompt

检索到资料后，把它拼进提示词：

```
你是一个严谨的公司制度助手，只能依据【参考资料】回答。
资料中没有答案时，回答"根据现有资料无法确定"，不要猜测。
每个结论后标注来源编号。

【参考资料】
[1] 员工手册-年假#0：员工入职满一年可享受 5 天年假，满三年 10 天，满五年 15 天。……
[2] 员工手册-年假#1：直属主管批准后生效。当年未休完的年假最多结转 5 天到次年。

【问题】年假有几天？
```

模型就能给出：

```
根据资料，入职满一年 5 天，满三年 10 天，满五年 15 天 [1]。
未休完的年假最多结转 5 天到次年 [2]。
```

### 6.4 这个玩具和工业级 RAG 差在哪

| 环节 | 玩具版 | 工业版 |
|---|---|---|
| 分词 | 字符二元组 | 专用 tokenizer / 嵌入模型 |
| 检索 | TF-IDF 余弦 | 向量检索 + BM25 混合 |
| 排序 | 无 | Cross-Encoder 重排 |
| 分块 | 定长切 | 按标题/语义切，保留元数据 |
| 文档解析 | 纯文本 | PDF/表格/OCR/多模态 |
| 兜底 | 分数阈值 | 置信度 + 规则 + 人工 |
| 评估 | 肉眼看 | recall@k、忠实性、A/B |

但骨架是一样的：**分块 → 索引 → 检索 → 组装 → 生成 → 兜底**。把这个流程跑通，再换更好的组件，就不会迷路。

## 七、RAG 的七个坑

### 坑 1：块切得太大或太小

- 太大：一个块里混着多个主题，检索精度下降，噪声变多；
- 太小：语义不完整，答案被切碎，模型拼不起来。

经验值：中文 200~500 字一块，重叠 10%~20%。但**没有万能值**，要按文档类型调：合同按条款切，论文按章节切，FAQ 按问答对切。

### 坑 2：只看关键词，不懂语义

用户问"如何请假"，文档写"休假申请流程"，关键词不重合，TF-IDF 就找不到。向量检索能缓解，但也会有"语义漂移"。工业界常用**混合检索**：BM25 保关键词，向量保语义，再融合排序。

### 坑 3：多跳问题

问："我们公司年假比法定多几天？" 需要先查公司年假，再查法定年假，再做减法。单次检索只能拿到一半资料。

解法：查询分解（把问题拆成子问题）、多轮检索、Agent 式"边查边想"。

### 坑 4：表格和图片

PDF 里的表格被解析成乱序文本，金额、日期全错位。需要专门的表格解析（如把表格转成 Markdown），或者多模态模型直接读图。

### 坑 5：资料冲突与时效

知识库里有新旧两版制度，检索都召回了，模型可能各取一半。需要**元数据（版本、生效日期）**，并在 prompt 里说明"以最新版本为准"。

### 坑 6：把不相关的内容也塞进去

top-k 取太大，噪声淹没信号；取太小，可能漏掉关键信息。**重排序**和**动态 k**（分数低于阈值就丢弃）比固定 k 更稳。

### 坑 7：没有评估

"感觉回答变好了"不是评估。没有评估集，你无法知道换 embedding、改分块、加 rerank 到底有没有用，甚至可能越改越差。

## 八、怎么评估一个 RAG 系统

评估要拆成两段：**检索质量**和**生成质量**。

### 8.1 检索评估

准备一批"问题 → 标准答案所在文档"的标注，然后看：

| 指标 | 含义 |
|---|---|
| Recall@k | 正确答案是否在前 k 个结果里 |
| Precision@k | 前 k 个里有多少是相关的 |
| MRR | 第一个相关结果排在第几位 |
| Hit Rate | 至少命中一个相关结果的问题比例 |

如果 Recall@5 只有 60%，后面生成再强也只能答对 60%。

### 8.2 生成评估

| 指标 | 含义 | 怎么测 |
|---|---|---|
| 正确率 | 答案对不对 | 人工标注 / 标准答案比对 |
| 忠实性（Faithfulness） | 是否忠于检索资料 | 人工核查 / NLI 模型 / LLM 评审 |
| 引用准确率 | 标注的来源对不对 | 规则校验 + 人工抽查 |
| 拒答率 | 该拒答时是否拒答 | 构造"资料中没有"的问题 |
| 幻觉率 | 编造事实的比例 | 人工标注 / 事实核查 |

### 8.3 建一个 50 条的小评估集

不需要一上来就搞几千条。先挑 50 个真实问题，覆盖：

- 常见问题（应该答对）；
- 边界问题（资料里有但不直接）；
- 无答案问题（应该拒答）；
- 多跳问题（需要组合）；
- 易混淆问题（相似但不同）。

每次改动后跑一遍，记录指标。**没有评估集的 RAG 优化，都是玄学。**

### 8.4 LLM-as-a-Judge 要谨慎

用 GPT-4 当评委很方便，但要注意：

- 评委也有偏好（喜欢长答案、喜欢自信语气）；
- 评委可能被答案的格式误导；
- 评委和人类的一致性需要校准。

最好人工抽检 10%~20%，和自动评分对齐后再大规模用。

## 九、RAG、微调、长上下文：怎么选

| 需求 | 首选 | 原因 |
|---|---|---|
| 私有知识、频繁更新 | RAG | 改知识库即可，不用重训 |
| 固定领域风格/格式 | 微调（SFT/LoRA） | 学行为，不学事实 |
| 一次性长文档理解 | 长上下文 | 全文都在，跨段关联 |
| 实时信息 | 搜索工具 | 训练数据永远滞后 |
| 精确计算 | 代码/计算器 | 生成模型不擅长算术 |
| 多跳复杂查询 | Agent + RAG | 边查边推理 |

它们不是互斥的。一个成熟系统往往是：

```
RAG 召回 → 长上下文整合 → 微调模型控制风格 → 工具校验关键数字 → 引用与人工复核
```

## 十、常见疑问

**Q1：RAG 能彻底消除幻觉吗？**
不能。检索错、资料错、模型误读、资料冲突，都会导致新的幻觉。RAG 把"凭记忆编"变成"开卷考试"，但开卷也可能抄错。

**Q2：直接把整篇文档塞进长上下文，不比 RAG 好吗？**
短文档可以，长文档不行：贵、慢、中间信息容易丢、无法引用、无法更新。RAG 是"先筛后读"，长上下文是"全读"，各有适用场景。

**Q3：微调能减少幻觉吗？**
能改善"行为"（比如学会拒答、学会引用格式），但不能可靠地注入新事实。用微调记知识，既贵又容易忘，不如 RAG。

**Q4：温度调到 0，幻觉就没了吗？**
没有。温度只影响采样随机性，不改变模型的知识空缺。它会让输出更稳定，但稳定地错也是错。

**Q5：怎么让模型说"我不知道"？**
三件事一起做：提示词明确允许拒答；SFT 数据加入"资料不足时拒答"的样本；评估体系奖励"该拒答时拒答"，而不是只奖励"答对"。

**Q6：小模型 + RAG 能替代大模型吗？**
很多场景可以。RAG 把"知识"外置后，小模型负责"理解和表达"，成本大幅下降。但复杂推理、多跳整合仍然更依赖模型能力。先做 RAG，再根据 bad case 决定要不要换更大的模型。

## 十一、总结

把这一篇压缩成一条链：

```
幻觉
  ├─ 事实性：不知道 / 记错 / 知识截止
  │     → RAG、工具、训练
  └─ 忠实性：没看资料 / 看漏了 / 自相矛盾
        → 提示词、引用、长上下文优化、微调

RAG
  文档 → 解析 → 分块 → 向量化 → 索引
  问题 → 改写 → 检索 → 重排 → 组装 → 生成 → 引用 → 兜底
  评估：Recall@k / 正确率 / 忠实性 / 拒答率
```

记住五句话：

1. **幻觉是生成模型的结构性副产品，不可能归零，只能管理。**
2. **先分清事实性还是忠实性**，再决定用 RAG、提示词还是微调。
3. **RAG 的核心不是"接个大模型"，而是"检索得准"**；检索错了，生成只会更自信地错。
4. **允许模型说"不知道"**，比反复要求"要准确"更有效。
5. **没有评估集，就没有优化**；先建 50 条，再谈调优。

动手建议：

1. 跑一遍第六节的代码，换成你自己的文档，看看检索结果；
2. 故意问一个资料里没有的问题，观察阈值兜底是否触发；
3. 把同一份资料分别用"整篇塞入"和"分块检索"两种方式喂给模型，对比准确率和成本；
4. 建一个 50 条的小评估集，记录 Recall@5 和忠实性，作为后续优化的基线；
5. 读一读 RAG 原论文（Lewis et al., 2020）和 *Lost in the Middle*，理解 Retrieval 与 Generation 的边界。

写到这里，「大模型基础」系列就告一段落了。我们从 token 出发，经过 GPT 结构、采样、训练、上下文，最后落到幻觉与 RAG。你会发现，这些看似独立的名词，其实串成了一条完整的链路：

```
文字 → token → 向量 → 注意力 → 概率分布 → 采样 → 输出
                  ↑
              预训练 / SFT / 对齐
                  ↑
              上下文 / KV Cache / RAG
```

理解这条链路，你再看任何新模型、新框架、新论文，都不会从零开始。
